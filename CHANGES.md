# Lightweight rewrite — 21 October 2026

The app now does one thing: keep the laptop and display awake while the toggle is ON and the lid is open. OFF returns control to Windows. It still starts ON. Minimizing keeps the request active; closing exits the process. The installed copy has not been replaced automatically.

**Removed the embedded browser.** Previously, Tauri/WebView2 rendered a page just to show one switch. Windows now draws the same warm paper layout, status label and switch directly. The new release executable is 108,032 bytes, compared with the old 3,073,536-byte executable, about 96.5% smaller. This is executable size, not a measured percentage reduction in RAM. The interface is static, with no grain filter, animation loop, maximize button or browser cache.

**Removed the periodic background work.** The old app kept a separate thread that woke every 25 seconds. The new app submits a continuous Windows keep-awake request from the UI thread and waits for Windows messages. There are no application-created worker threads or timers. Windows itself can create helper threads, so Task Manager can still show more than one thread.

**Stopped rewriting Windows power settings.** The old version launched multiple `powercfg` commands to change sleep, hibernate and lid actions. It could change settings even when reading the originals failed, ignore command failures, and show ON without checking the keep-awake API result. The new version only changes its own temporary execution request, checks the result and shows an error if it fails. It does not enable away mode, change the power plan or override lid-close behavior, as requested. Closing or terminating the process ends its request. Manual Sleep, laptop lid behavior and system policies still apply.

**Removed unused files and toolchains from this workspace.** Deleted the old C# browser/server prototypes, their DLLs and executable, the Tauri project and its compiled output, npm dependencies and manifests, unused Android/iOS/macOS icons, old HTML/JavaScript UI, personal-image preview copies, obsolete screenshot and stale handoff notes. The old Tauri tree alone occupied 4,594,618,779 bytes; npm dependencies occupied another 15,621,384 bytes. These were disk usage, not resident RAM. Git history and your installed application were left intact.

**Checked the result.** `docs/verification.json` contains the latest measured RAM, idle CPU time, child-process count and toggle checks; `docs/native-on.png` and `docs/native-off.png` show the native UI. Five hundred toggles kept GDI resources steady, and the power-plan snapshot matched before and after. These are short-run measurements on this laptop, not a guarantee about every Windows machine or long-term behavior. Reading the system-wide live request list with `powercfg /requests` requires elevation in this session; the native test instead verifies the owning thread's execution flags. Clippy and rustfmt are not installed here, so those optional checks were unavailable.

**Apply this to your local app.** Close the old app normally first. Copy `dist\BrutalAwake.exe` into `%LOCALAPPDATA%\Brutal Awake\` and rename the copied file to **`brutal-awake.exe`**, replacing the old file. The hyphen matters because your existing shortcut uses that filename. No extra files or installation are needed. Source changes alone do not update that installed executable.

Windows API behavior: [Microsoft's SetThreadExecutionState documentation](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate).
